# PushLedger — 푸시 알림 가계부

결제 알림을 읽어 가계부에 자동으로 꽂는 안드로이드 앱. 규칙으로 먼저 읽고,
규칙이 놓친 것은 AI 로 넘긴다 — 손으로 골라 넘겨도 되고, 자동으로 넘기게 켜 둬도 된다.

### ⬇ APK 내려받기

**[pushledger.apk 바로 받기](https://github.com/aidennis0297-art/ledger/raw/main/pushledger.apk)**

폰 브라우저에서 위 링크를 누르면 바로 받아진다. 설치할 때 "출처를 알 수 없는 앱"
허용이 필요하고, 앱을 처음 열면 **알림 접근 권한**을 켜야 한다 — 이걸 안 켜면
다른 앱의 알림을 읽을 수 없어서 앱이 아무것도 하지 못한다.

## 왜 안드로이드 네이티브인가

핵심 기능이 "다른 앱의 알림 읽기"다. 이건 `NotificationListenerService` 로만 되고
안드로이드 전용이다. iOS 는 OS 차원에서 막혀 있고 웹도 불가능하다. Flutter 나
React Native 로 감싸도 결국 이 네이티브 서비스를 붙여야 해서 레이어만 하나 는다.

Kotlin + Jetpack Compose, minSdk 26, compileSdk 36. 의존성은 최소로 두었다.
Room 대신 JSON 파일, Retrofit 대신 OkHttp, DI 프레임워크 없음, 차트 라이브러리 없음.

## 알림이 거래가 되는 길

```
알림 도착
  ├ 안 보기로 한 앱         → 버림 (알림함에도 안 남김)
  ├ 허용 목록 밖            → 그래도 전부 남긴다. 금액이 보이면 [안 켠 앱], 아니면 [금액 없음]
  └ 허용 목록 안            → 결과가 무엇이든 알림함에 남긴다
       └ 규칙 파싱 (Parser.kt)
            ├ 결제      → 거래로 확정            → 알림함 [기록됨]
            ├ 송금 보냄 → 지출로 확정            → 알림함 [기록됨]
            ├ 입금      → 수입으로 확정          → 알림함 [기록됨]
            ├ 상대 수령 → 아무것도 안 함         ← 보낼 때 이미 셌다
            ├ 취소      → 원 거래를 찾아 무효화   ← 수입으로 넣지 않는다
            ├ 실패      → 알림함 [미처리] → AI 로 넘김
            └ 금액 없음 → 알림함 [금액 없음] → 낱개로 AI 에 넘길 수 있음
```

**차단한 앱 말고는 폰에 오는 알림을 전부 쌓는다.** 예전에는 금액이 보이는 것만 남겼는데,
그러면 결제 알림이 금액을 특이한 꼴로 적어 오는 앱은 흔적조차 없이 사라져서 왜 안 잡혔는지
확인할 방법이 없었다. 이제는 다 남기고 상태로만 갈라 놓는다.

원문은 설정 › 데이터의 **알림 기록 CSV** 로 통째로 뽑을 수 있다. 파일에서 직접 읽으므로
화면이 들고 있는 상한(최근 3,000건)에 잘리지 않는다. 규칙이 왜 못 읽었는지는 원문을 봐야
알 수 있고, 원문은 이 앱 안에만 있다.

양이 늘어난 만큼 두 곳에 상한을 뒀다. 같은 알림이 갱신되며 다시 오는 것을 막는 검사는
최근 400건만 훑고(다시 오는 건 몇 분 안의 일이다), 화면이 들고 있는 목록은 3,000건에서
자른다. 파일에는 보관 기간만큼 다 남는다.

### 같은 결제가 여러 번 들어오는 것을 막는 법

한 번 결제하면 카카오페이·카드사·은행이 **각자** 알림을 띄운다. 앱마다 가맹점 표기가
다르고(`스타벅스` / `스타벅스강남R점` / 빈칸) 패키지명도 당연히 다르다. 그래서
`Store.addTxn` 은 **금액과 시각만** 본다 — 같은 금액이 10초 안에 또 들어오면 같은
결제다. 대가로 10초 안에 같은 금액을 두 번 쓴 진짜 결제는 한 건으로 뭉치는데,
여러 줄로 부풀어 예산이 틀리는 쪽이 훨씬 자주 아프다.

### 가맹점 이름은 저장 전에 다듬는다

알림에 찍히는 이름은 결제사가 붙인 것들로 덮여 있다. `Merchant.kt` 가 한 번에 벗긴다.

| 들어온 이름 | 남는 이름 |
|---|---|
| `[체크](주)김밥천국` | `김밥천국` |
| `토스페이_스타벅스` | `스타벅스` |
| `아파트관리비 8월분` | `아파트관리비` |
| `(주)우아한형제들` | `배달의민족` |
| `에스씨케이컴퍼니` | `스타벅스` |

두 가지를 내놓는다. `clean()` 은 화면과 기록에 남길 이름이고 지점명을 남긴다 — 어느
지점에서 썼는지는 뜻이 있는 정보다. `key()` 는 비교용 열쇠로 지점명·공백·기호까지 턴다.

**청구서 꼬리표를 떼는 것이 반복 결제 감지의 핵심이다.** `8월분`, `2026.08`, `3회차`,
`1/12회` 를 안 떼면 8월 관리비와 9월 관리비가 서로 다른 가게가 되어, 정작 매달 나가는
청구서를 통째로 놓친다.

### 카드사 알림의 흔한 꼴

카카오가 공개한 [카드 SMS 파서](https://github.com/kakao/credit-card-sms-parser)(지금은
보관 상태)의 렉서 규칙을 읽고, 거기서 다루는데 여기 없던 것들을 채웠다.

- **전각 공백(U+3000)** — 자바 정규식의 `\s` 는 이 글자를 공백으로 안 본다. 카드사
  알림에는 흔히 섞여 오는데, 그러면 `스타벅스　강남점` 이 통째로 한 덩어리가 되어
  토큰이 안 쪼개진다.
- **가려진 이름 `김*수님`** — 은행과 간편결제는 이름을 가려 보내는 일이 훨씬 많다.
  한글만 받는 규칙으로는 그런 알림에서 상대를 통째로 못 뽑아 송금 방향 판정이 죽는다.
- **`국민(1234)` 같은 카드 토큰** — 괄호만 지우면 `국민` 이 남아 가맹점 후보가 된다.
  카드사 이름과 뒷자리를 통째로 지운다.
- **눌어붙은 결제 낱말** — `이마트사용` 처럼 띄어쓰기 없이 붙어 온다. 이건 거르기 **전에**
  떼야 한다. `사용` 이 들어 있다는 이유로 토큰째 버려지고 있었다.

### 조사는 받침으로 가른다

`한국장학재단에서` 가 그대로 가맹점 이름이 되어 있었다. 그렇다고 끝의 조사를 무턱대고
지우면 멀쩡한 이름이 깎인다 — `코나아이` 에서 `이` 를 떼면 `코나아` 가 된다.

사전 없이 이걸 가르는 방법이 한국어 문법 안에 있다. **조사는 앞 글자의 받침 유무로 짝이
갈린다.** 받침이 있으면 은·이·을·과·으로, 없으면 는·가·를·와·로가 붙는다.

| 토큰 | 앞 글자 | 받침 | 조사가 요구하는 것 | 결과 |
|---|---|---|---|---|
| `무신사가` | 사 | 없음 | `가` → 받침 없음 | 짝 맞음 → `무신사` |
| `코나아이` | 아 | 없음 | `이` → 받침 있음 | 안 맞음 → 그대로 |
| `올리브영은` | 영 | 있음 | `은` → 받침 있음 | 짝 맞음 → `올리브영` |

한글 음절은 `(코드 - 0xAC00) % 28` 이 종성 번호라 그 값이 0이면 받침이 없다(`Hangul.kt`).
형태소 분석기를 붙이면 더 정확하겠지만 사전만 수십 MB다. 가맹점 이름 한 토막을 다듬는 데
그만한 것을 들일 이유가 없다.

### 사용자가 고친 분류를 기억한다

규칙과 AI 는 가맹점 이름만 보고 짐작하는 것이라 **같은 곳을 매번 같은 식으로 틀린다.**
내역에서 한 번 고치면 그 가맹점(`Merchant.key`)의 분류를 `Config.catMemory` 에 적어 두고,
다음부터 규칙보다도 AI 보다도 그것을 먼저 쓴다. 지점이 달라도 같은 열쇠라 강남점을 고치면
역삼점도 따라온다. AI 검토 제안을 받아들이는 것도 사용자가 그 분류를 정한 것으로 본다.

거래 데이터 보강 업계에서 쓰는 방식과 같다 — 정규화 → 별칭 매핑 → 규칙 우선, AI 는 빈틈만,
그리고 **사용자 교정을 되먹임**. 고칠 때마다 다시 고쳐야 하는 앱은 결국 안 쓰게 된다.

### 송금은 조사로 방향을 가른다

카카오페이·토스는 보낸 쪽과 받은 쪽 모두에게 알림을 띄우고 문구가 거의 같다.

| 문구 | 뜻 | 처리 |
|---|---|---|
| `○○님에게 …보냈어요` | 내 돈이 나감 | 지출 |
| `○○님이 …보냈어요` | 내 돈이 들어옴 | 수입 |
| `○○님에게 …받았어요` | 내 돈이 들어옴 | 수입 |
| `○○님이 …받았어요` | 내가 보낸 걸 상대가 찾아감 | **아무것도 안 함** |

마지막 줄을 수입으로 세는 바람에 보낸 돈이 그대로 내 수입으로 잡혔다.
AI 프롬프트에도 같은 표를 넣어 두 경로가 같은 판단을 하게 했다.

다만 `○○님이 **보낸** 10,000원을 받았습니다` 는 셋째 줄이 아니라 둘째 줄이다.
`님이` 는 `보낸` 의 주어일 뿐이고 `받았` 의 주어는 생략된 나다. 조사만 보면 이걸
"상대가 받음" 으로 읽어 버려서, `님이` 뒤에 `보낸/보냈` 이 오면 그 규칙에서 뺀다.

### 정산금은 수입이 아니라 되받은 돈이다

더치페이는 내가 먼저 다 내고 나중에 나눠 받는다. 그 돈을 수입으로 세면 그날 지출과
수입이 같이 부풀어 두 숫자가 다 틀리고 예산은 실제보다 빡빡해진다. 4만원짜리 저녁을
내가 긁고 셋이 1만원씩 보내면 내 지출은 1만원이다.

`Store.applySettlement` 이 직전 24시간 지출 중 **정산금보다 큰 것 가운데 가장 최근
건**을 찾아 그만큼 깎는다. 작은 결제를 깎아 음수로 만들 수 없고, 여러 건이 걸리면
방금 낸 것일 가능성이 가장 높다. 짝을 못 찾으면 그냥 받은 돈이었을 수 있으니 수입으로 넣는다.

고친 자국은 `Fix` 로 남아 내역 탭의 AI 검토 카드에서 **되돌릴 수 있다.** 이미 적어 둔
기록을 자동으로 줄이는 일이라 소리 없이 지나가면 안 된다.

## 결제 취소를 다루는 방식

취소 알림이 오면 **새 수입 거래를 만들지 않는다.** 금액과 가맹점으로 최근 두 달을
거슬러 원 거래를 찾아 `canceled` 표시를 남긴다.

- 거래 기록은 지우지 않는다. 내역 화면에 취소선으로 계속 보인다.
- 모든 통계는 `Stats.active()` 를 거치므로 취소된 거래는 어느 그래프에도 안 나온다.
- 원 거래를 못 찾은 취소 건은 조용히 버리지 않고 알림함에 남겨 사용자가 고르게 한다.

수입으로 기록하면 5만 원을 쓰고 취소했을 때 지출 5만 + 수입 5만이 되어 소비가
실제보다 많아 보인다. 무효화 방식이면 지출 합계·카테고리 비중·예산 소진율이 전부
자연스럽게 맞는다.

## 데이터를 나눠 담는 방식

로그가 쌓여 앱이 느려지는 걸 막으려고 파일 성격에 따라 쪼개는 단위를 다르게 뒀다.
전부 앱 전용 저장소(`filesDir`) 안의 JSON 이다.

| 경로 | 단위 | 이유 | 보관 |
|---|---|---|---|
| `ledger/YYYY-MM.json` | 월별 | 거래는 영구 보관. 월 단위면 한 파일이 수백 건에 그친다 | 영구 |
| `inbox/YYYY-MM-DD.json` | **일별** | 원본 알림은 양이 많고 대부분 버릴 것. 날짜째 통으로 지우려면 일별이어야 한다 | 기본 30일 |
| `config.json` | 단일 | 예산·고정지출·목표·허용 앱 | 영구 |

앱을 켤 때 읽는 건 이번 달 거래 파일 하나뿐이라 몇 년을 써도 시작 속도가 같다.
보관 기간이 지난 알림 파일은 `Store.sweep()` 이 날짜째 지운다.

집계 캐시는 일부러 두지 않았다. 월 파일을 그때그때 스캔하는 편이 무효화 버그보다 싸다.
한 해치 스캔이 눈에 띄게 느려지면 그때 `stats/YYYY-MM.json` 을 붙이면 된다.

## 탭 구성

**홈** — 이번 달 남은 예산(큰 숫자 + 진행 바), 오늘/이번 주 지출, 이번 달 흐름 미니 차트,
여유비 목표 진행률, 고정지출 D-day, 최근 내역 5건. 인식 못 한 알림이 있으면 맨 위에 띄운다.

**내역** — 월 이동, 날짜별 그룹(헤더에 그날 합계), 가맹점 검색, 카테고리 필터.
항목을 누르면 가맹점·금액·카테고리·메모를 고치고, **결제 취소 처리 / 취소 되돌리기 / 삭제**를
할 수 있다. 취소와 삭제는 다르다. 취소는 기록으로 남는다.

**알림함** (홈 우측 상단 서랍) — 프로그램이 완벽하지 않다는 전제로 만든 화면.

**켜 둔 앱의 알림은 결과가 무엇이든 전부 여기 남는다.** 잘 읽힌 것까지 남기는 이유는,
성공한 건이 안 보이면 알림함이 고장난 것만 모인 곳이 되고 무엇이 들어와서 어떻게
읽혔는지 확인할 데가 없어지기 때문이다. 상태로 갈라 담는다.
- *미처리* : 금액이 보이는데 규칙이 못 읽은 것. `모두 AI로 처리` 의 대상이다.
- *기록됨* : 규칙이나 AI 가 거래로 만든 것. 사유 줄에 무엇으로 읽혔는지 적힌다.
- *실패* : AI 도 못 읽은 것. 여기 있는 건 낱개로든 일괄로든 **다시 시도**할 수 있다.
- *무시됨* : 사용자가 넘긴 것, 지출이 아닌 것, 10초 중복으로 건너뛴 것.
- *금액 없음* : 켠 앱에서 왔지만 금액이 안 보이는 알림. 결제인데 여기 들어와 있으면
  그 줄에서 바로 AI 에 넘길 수 있다.
- *앱 관리* : 알림이 들어온 앱 목록 + 수집 스위치. `이 앱 안 보기` 를 누른 앱은
  그때부터 흔적도 남기지 않는다.

AI 분석 진행 상황은 **어느 탭에 있든 화면 위쪽 띠에 뜬다.** 큐는 앱을 나가도 돌고,
끝난 결과("N건 처리, M건 실패")는 사용자가 닫을 때까지 남는다.

**알림함에서 한 일은 전부 되돌릴 수 있다.** 한 번 누르면 끝인 처리가 하나도 없어야
사용자가 버튼을 겁내지 않는다.

| 한 일 | 되돌리는 법 |
|---|---|
| 무시 | 그 줄의 `무시 취소`, 또는 무시됨 칸에서 `전부 되돌리기` |
| 이 앱 안 보기 | 앱 관리에서 다시 켜면 그때 묻힌 알림까지 함께 되살아난다 |
| AI 가 잘못 기록 | 그 줄의 `기록 취소`(거래도 같이 삭제), 또는 기록됨 칸에서 `전부 되돌리기` |
| AI 실패 | 실패 칸에서 낱개로든 통째로든 `다시 시도` |
| 금액 없음으로 묻힘 | 그 줄에서 바로 `AI로 읽기` |

기록됨 칸의 일괄 되돌리기는 **AI 가 만든 것만** 지운다. 규칙이 읽은 건 정확도가 다르고,
같이 지우면 멀쩡한 가계부가 통째로 날아간다.

**통계** — 맨 위 칩으로 *월간* 과 *연간* 을 갈아 끼운다.

월간은 축을 여섯으로 나눠 본다. 주 고르기 칩이 아래 그래프 전부에 같이 걸린다.
- *일별* : 막대 / 추이 전환, 하루 평균 예산선 겹쳐 보기
- *주간* : 월 안의 1주차부터 (ISO 주차는 달을 넘나들어 가계부에선 헷갈린다)
- *시간대* : 0~23시 막대 + 가장 많이 쓰는 시각
- *요일 × 시간* : 168칸 히트맵
- *항목별* : 도넛 + 비중 범례
- *요일별*, *자주 간 곳 TOP 10*, 전월 대비 증감

연간은 축이 다르다. 한 해를 볼 때 궁금한 건 "어느 달에 무너졌는가" 하나라서
시간대·요일·히트맵이 없다. 월별 막대 12칸, 월 평균과 가장 많이 쓴 달, 항목별 도넛,
가맹점 TOP, 전년 대비 증감. 평균은 기록이 있는 달 수로만 나눈다.

**예산** — 월 예산, 항목별 예산, 투자·저축 목표, 고정지출(월세·관리비·구독) 추가/삭제,
그리고 **반복 결제 감지**. 네 가지를 다 넘겨야 구독으로 본다 — 서로 다른 달에 세 번 이상,
한 달에 한 번씩만, 금액이 중앙값에서 20% 안, **이웃한 결제 사이의 간격이 25~35일**.
마지막 조건이 "석 달 연속 비슷한 값을 쓴 단골 식당" 을 걸러 낸다.

간격은 날짜 숫자(3일, 29일)를 빼지 않고 **실제 날짜 사이의 일수**로 센다. 그래야 말일
구독이 저절로 풀린다 — 7월 31일과 8월 30일은 날짜 숫자로는 하루 차이지만 실제로는 30일
간격이고, 그게 우리가 보려는 값이다. 날짜 숫자로 재면 달을 넘나드는 경우마다 예외를
손으로 붙여야 하고 그 예외가 또 틀린다. `안 볼래요` 를 누른 곳은
`Config.ignoredRecurring` 에 남아 다시 권하지 않는다.
(상태창 알림·데이터 내보내기·NVIDIA API 키·예시 데이터는 홈 우측 상단의 설정 서랍에 있다.)

## AI 에게 주는 틀

모델은 `deepseek-ai/deepseek-v4-flash-0731`, 엔드포인트는
`https://integrate.api.nvidia.com/v1/chat/completions`, 응답은 스트리밍 없이 한 번에 받는다.

AI 를 쓰는 자리는 둘인데 **성격이 정반대라 호출 설정도 갈라 뒀다** (`Nvidia.call`).

| | 알림 파싱 | 코치 리포트 |
|---|---|---|
| 생각 모드 | **끔** | 켬 (`reasoning_effort: high`) |
| `max_tokens` | 400 | 16384 |
| `temperature` | 0.0 | 0.3 |

프롬프트에서 분류 목록은 `CATS` 한 벌로 모아 두 프롬프트가 나눠 쓴다. 같은 표를 두 벌
적어 두면 한쪽만 고쳐지고, 그때부터 알림은 A 로 분류되는데 검토는 B 로 고치라고 한다.
줄바꿈과 불릿을 걷어내 알림 파싱 프롬프트는 1,545자에서 822자로, 검토 프롬프트는
1,187자에서 654자로 줄었다. 알림 한 건마다 실려 나가는 글자라 길이가 곧 돈이다.

알림 한 줄에서 금액과 가맹점을 뽑는 데는 생각할 것이 없다. 그런데 여기에도 생각 모드가
켜져 있어서 알림 한 건에 수십 초가 걸렸다 — 스무 건이면 십 분이다. 게다가 응답이 생각
과정만 쓰다가 상한에 걸려 JSON 이 통째로 안 나오는 일도 잦았다. 파싱은 끄고 짧게 받는다.

출력은 JSON 한 덩어리로 못 박고 카테고리를 `Cat` 의 일곱 개와 그 세부 분류로 제한한다.
자유롭게 두면 같은 카페를 "커피", "음료", "스타벅스" 로 제각각 적어 통계가 조각난다.

```json
{"is_expense":true,"is_cancel":false,"amount":12000,"merchant":"스타벅스강남점",
 "category":"식비","sub_category":"카페/음료","method":"카드","confidence":0.95}
```

결제 알림이 아니면 `{"is_expense": false, "reason": "..."}`.
프롬프트에는 위의 **송금 방향 표**도 함께 넣는다. 규칙과 AI 가 서로 다른 판단을 하면
같은 알림이 어느 경로로 처리됐는지에 따라 수입이 됐다 안 됐다 한다.

응답에서 JSON 을 꺼낼 때는 여는 중괄호부터 **짝이 맞는** 닫는 중괄호까지만 자른다.
마지막 중괄호까지 통째로 자르면, 모델이 JSON 뒤에 설명을 덧붙이며 중괄호를 한 번 더 쓸 때
두 덩어리가 붙은 채 넘어와 파싱이 깨진다.

**키가 없어도 쓸 수 있다.** 알림함의 못 읽은 줄마다 `직접 입력` 버튼이 있고, 누르면
내역 탭과 같은 편집 다이얼로그가 **금액과 가게 이름이 채워진 채로** 열린다. 규칙이
거래로 못 만든 알림이라도 금액과 이름은 대개 보이기 때문이다(`Parser.salvage`).
빈 칸에서 시작하면 사람은 대개 안 넣는다. 저장하면 그 알림 줄도 함께 정리된다.

**자동 분석** (설정 › AI 자동 분석, 기본 꺼짐): 켜 두면 규칙이 못 읽은 결제 알림이
들어오는 그 자리에서 AI 큐에 붙는다. 앱을 열어 둘 필요도, 버튼을 누를 필요도 없다.
알림이 몰아쳐 들어와도 `enqueueUniqueWork(APPEND)` 로 한 번에 하나씩만 돈다 —
열 개를 동시에 부르면 API 쪽에서 막힌다. 자동으로 잘 처리된 건은 조용히 지나가고,
실패한 것만 알림함과 결과 줄에 남는다. 알림 한 건마다 API 를 부르므로 요금이 붙는다.

### 이미 기록된 것도 AI 가 다시 본다

규칙이 만든 기록은 **조용히** 틀린다. 가맹점 자리에 카드사 이름이 앉거나, 편의점
결제가 엉뚱한 칸으로 가거나, 광고 알림이 지출로 들어와도 아무 신호가 없다. 못 읽은
알림은 알림함에 쌓이기라도 하지만, 잘못 읽은 기록은 사용자가 우연히 내역을 훑다
발견하기 전까지 그대로 남는다.

내역 탭의 **AI 기록 검토**(`AiReview.kt`)가 그 자리다. 그달의 자동 기록(`by` 가
`rule`/`ai` 인 것)을 열다섯 건씩 묶어 보내고, 고칠 것만 제안으로 돌려받는다.
묶어 보내면 호출 수가 줄 뿐 아니라 모델이 줄끼리 견주어 보기까지 한다 — 같은
가맹점이 두 줄에서 다르게 분류돼 있으면 그 자리에서 걸린다.

**고침은 자동으로 적용하지 않는다.** AI 도 틀리는데 소리 없이 적용되면 틀린 기록이
다른 틀린 기록으로 바뀔 뿐이고 사용자는 그것도 모른다. 제안으로 쌓아 두고
무엇이 무엇으로 바뀌는지 보여 준 다음 사용자가 누른다. 적용한 뒤에도 되돌릴 수 있게
원래 줄을 통째로(`Fix.before`) 들고 있는다 — 바뀐 칸만 적어 두면 되돌릴 때
그 칸이 그동안 또 바뀌었는지 알 수 없어서 되돌리기가 덮어쓰기가 된다.

손으로 넣은 건과 고정지출은 검토 대상이 아니다. 사용자가 직접 정한 것을 AI 가
다시 고치라고 권하면, 고쳐 놓을 때마다 같은 제안이 또 올라온다.

**오래 걸리는 일의 규칙 세 가지** — 이 앱에서 AI 는 전부 이 규칙을 따른다.
- *진행이 보인다* : 알림 분석도 기록 검토도 리포트 생성도 **어느 탭에 있든** 화면 위
  띠에 뜬다. 셋이 각자 진행 상태를 들고 있으면 같은 모양의 띠를 세 벌 그리게 되므로,
  `AiJob` 하나에 모아 보고하고 화면은 그것만 구독한다.
- *이동이 자유롭다* : WorkManager 큐(`AiWorker`)와 앱 수명 코루틴(`CoachRun`)에서 돌아서
  탭을 옮기든 앱을 나가든 계속된다. 화면 안에서 돌리면 화면이 사라질 때 일도 같이 죽는다.
- *결과가 남는다* : 끝난 요약은 `Config.lastAiRun` 에 적혀 사용자가 닫을 때까지 남는다.
  진행 바 안의 글자로만 두면 큐가 끝나는 순간 진행 바와 함께 사라진다.

실패한 건은 알림함 *실패* 칸에 모이고, 낱개로든 일괄로든 다시 시도할 수 있다.
호출 자체가 실패하면 워커가 한 번은 자동으로 다시 걸어 본다.

API 키는 앱 전용 `SharedPreferences`(`pushledger_nvidia`)에 평문으로 있다. 다른 앱은
읽을 수 없지만 암호화는 아니다 — 루팅된 기기나 백업 경로로는 노출될 수 있다.

## 빌드

```bash
gradlew assembleDebug
```

- `local.properties` 의 `sdk.dir` 는 슬래시로 적는다 (`sdk.dir=C:/Android/Sdk`).
  역슬래시를 쓰면 Properties 문법에서 이스케이프로 먹혀 경로가 깨진다.
- 프로젝트 경로에 한글이 있어서 `gradle.properties` 에 `android.overridePathCheck=true`
  를 넣었다. NDK 를 쓰지 않으므로 **APK 빌드는 이 상태로 된다** (확인함).
- 다만 **유닛 테스트는 한글 경로에서 돌지 않는다.** 클래스는 정상적으로 컴파일되는데
  Gradle 테스트 워커가 `ClassNotFoundException` 을 낸다. 같은 소스를 ASCII 경로에
  복사하면 32개 전부 통과한다. 테스트를 돌리려면 둘 중 하나를 하면 된다.
  - 프로젝트를 ASCII 경로로 옮긴다 (예: `C:\dev\pushledger`)
  - 또는 정션을 걸어 ASCII 경로에서 빌드한다:
    `cmd /c mklink /J C:\dev\pushledger "C:\Users\denni\OneDrive\문서\pushledger"`
- 검증된 조합: Gradle 8.14.3 / AGP 8.13.0 / Kotlin 2.2.20 / JDK 21(Android Studio JBR).
- **release 서명 비밀번호는 `keystore.properties` 에 있다.** 이 파일과 `release.keystore`
  는 `.gitignore` 대상이라 저장소에 올라가지 않는다. 파일이 없는 곳에서는 서명 설정을
  아예 만들지 않으므로 `assembleRelease` 가 서명되지 않은 APK 를 낸다. 폰을 바꾸거나
  다른 컴퓨터에서 빌드하려면 이 두 파일을 따로 옮겨야 한다.

  ```properties
  storePassword=...
  keyAlias=pushledger
  keyPassword=...
  ```

APK 는 `app/build/outputs/apk/debug/app-debug.apk` 에 나온다.

## 폰에 넣은 뒤 처음 할 일

1. APK 설치 (출처를 알 수 없는 앱 설치 허용 필요)
2. 앱을 열면 상단에 뜨는 **알림 접근 권한 켜기** — 이걸 안 켜면 아무것도 못 읽는다
3. 예산 탭에서 월 예산, 고정지출, NVIDIA API 키 입력
4. 결제를 한 번 해 보고 알림함을 확인. 안 잡히면 *앱 관리*에서 해당 앱을 켠다

## 금액을 적는 법

```
1000000   → 100만원          123456    → 12만 3456원
3456      → 3456원           123456789 → 1억 2345만 6789원
```

`Money.kt` 의 `won()` 하나가 이 표기를 만든다. 화면·상태창·위젯·AI 리포트가 전부
여기를 지나므로, 표기를 바꾸려면 그 함수 하나만 고치면 된다.

예전에는 `%,d원` 으로 세 자리마다 쉼표를 찍었다. 1,000,000 은 자릿수를 세어야 백만인 줄
알 수 있는데 사람은 만 단위로 끊어 읽는다. 만 아래는 쉼표를 넣지 않는다 —
"12만 3,456원" 이 되면 끊는 자리가 두 종류가 되어 만 단위 끊기가 눈에 안 들어온다.

격자로 읽어 내는 방식이었는데, 그렇게 나온 글자는 읽을 수는 있어도 볼 만하지 않았다.
획 굵기가 제멋대로고 받침이 위 글자에 붙었다. 한글을 도트로 그리는 일은 사람이
11,172자를 하나씩 손보는 일이고, 그 일은 이미 되어 있었다.

글꼴은 `MainActivity` 에서 `LocalTextStyle` 에 한 번만 건다. 화면마다 `fontFamily` 를
적어 두면 새 화면에서 빠뜨리는 순간 그 줄만 시스템 폰트로 튄다. 입력칸처럼 우리가
만들지 않은 컴포넌트도 이 값을 읽는다. 다만 `TextStyle()` 을 통째로 새로 만드는
자리(순위 배지, 입력칸)는 상속이 끊기므로 거기만 `fontFamily = Pixel` 을 직접 적었다.

큰 글자 두 단은 11의 배수에 맞춰 뒀다 — `Display 33sp`(11×9), `Amount 22sp`(11×6).
픽셀 폰트는 설계 크기의 정수 배에서 픽셀이 정확히 떨어진다. 화면에서 제일 크게 보이는
숫자라 흐려지면 바로 티가 난다.

차트 안의 숫자는 여전히 3×5 도트로 직접 찍는다(`Dots.kt`). 그건 글자가 아니라 그래프의
일부라, 막대와 같은 격자·같은 알갱이 크기로 앉아야 한다.

APK 는 폰트 때문에 약 0.9MB 늘었다(압축 후 791KB).

## 도트 그래픽

픽셀은 **악센트로만** 쓴다. 글자와 여백은 깔끔한 화이트로 두고, 그림에 해당하는 것만
도트로 찍는다. 화면 전체를 픽셀화하면 세련된 화이트가 아니라 그냥 옛날 게임이 된다.
한글 픽셀 폰트를 억지로 넣지 않은 것도 같은 이유다.

재료는 `ui/Dots.kt` 한 파일에 모여 있다.

- `DOT` / `DOT_GAP` — 도트 한 칸과 간격. **이 두 숫자만 바꾸면 화면 전체의 결이 같이 움직인다.**
- `DotIcons` — 카테고리 11개의 8×8 픽셀 아이콘. `'#'` 이 찍히는 칸이라 모양을 고치려면
  글자만 바꾸면 된다. 포크와 나이프(식비), 손잡이 컵(카페), 버스, 쇼핑백, 전구, 십자,
  음표, 신호, 집, 동전, 말줄임.
- `dotBar` — 바닥부터 쌓는 도트 기둥. 막대그래프 한 칸
- `dotTrack` — 가로로 채우는 도트 띠. 예산 소진율, 순위 막대
- `dotArc` — 각도마다 점을 찍는 원호. 도넛 조각
- `dotField` — 배경에 아주 옅게 까는 격자. 홈 상단 큰 숫자 뒤에만 깐다

적용된 곳:

| 위치 | 도트로 바뀐 것 |
|---|---|
| 일별·주간·시간대·요일 막대 | 값이 도트 개수로 양자화된다. 눈금 없이 알갱이를 세어 읽는다 |
| 일별 추이선 | 도트 간격으로 끊어 찍은 점선. 아래는 옅게 채워 양감을 준다 |
| 예산선 | 실선이 아니라 끊어 찍은 도트라 차트와 같은 결로 보인다 |
| 항목별 도넛 | 3겹 도트 링. 조각 사이를 한 칸 띄워 경계를 만든다 |
| 요일 × 시간 히트맵 | 168칸 정사각 도트. 농도만으로 표현한다 |
| 예산 소진 / 순위 막대 | 도트 세그먼트. 초과하면 색이 뒤집힌다 |
| 내역 줄 카테고리 배지 | 원형 글자 대신 8×8 픽셀 아이콘 |
| 고정지출 D-day, 도넛 범례 | 동그라미를 전부 사각 도트로 |

레이아웃·타이포·Material 아이콘은 건드리지 않았다. 도트는 데이터가 있는 자리에만 있다.
